# 웹사이트 PRD

펀드형 피트니스 식품 공동구매 플랫폼

v0.1 | 2026.03

---

## 1. 개요

### 1-1. 이 문서의 목적

웹사이트를 만들기 위해 필요한 모든 것을 정리한 문서다. 어떤 페이지가 필요하고, 각 페이지에서 유저가 뭘 하고, 데이터는 어떻게 흘러가는지를 담는다.

### 1-2. MVP 범위

세 개의 웹(구매자, 셀러, 어드민)이 최종 목표지만, **첫 버전에서는 구매자 웹 하나만 만든다.**

| 웹 | MVP | 대체 수단 |
|----|-----|----------|
| 구매자 웹 | 직접 개발 | - |
| 셀러 웹 | 안 만듦 | DB 직접 입력 + 구글시트로 배송지/정산 공유 |
| 어드민 웹 | 안 만듦 | 노션 + 구글시트 + Supabase 대시보드 |

셀러가 5곳 미만일 때 셀러 전용 웹은 불필요하다. 상품 등록, 펀드 개설, 배송지 전달, 정산 — 전부 수동으로 처리할 수 있다.

### 1-3. 기술 스택

| 영역 | 기술 | 선택 이유 |
|------|------|----------|
| 프론트엔드 | Next.js (App Router) | SSR + 정적 생성, 1인 개발에 빠름 |
| 스타일링 | Tailwind CSS | 유틸리티 기반, 빠른 UI 개발 |
| 백엔드/DB | Supabase (PostgreSQL) | 인증, DB, 실시간 구독, 스토리지 올인원 |
| 결제 | 토스페이먼츠 | 한국 PG 중 연동 문서 가장 잘 돼 있음, 부분환불 지원 |
| 배포 | Vercel | Next.js 최적화, 무료 티어로 시작 가능 |
| 이미지 저장 | Supabase Storage (또는 S3) | 상품 이미지 업로드/서빙 |

### 1-4. 핵심 설계 원칙

**모바일 우선.** 유저의 90%가 카카오톡 인앱 브라우저 또는 모바일 크롬/사파리로 들어온다. 데스크톱은 나중에 대응한다.

**빠른 로딩.** 상품 상세 페이지가 3초 안에 뜨지 않으면 이탈한다. 이미지 최적화, 서버사이드 렌더링 필수.

**공유가 쉬워야 한다.** 모든 펀드 페이지에 카카오톡 공유, 링크 복사 버튼이 있어야 한다. 공유된 링크를 열었을 때 바로 상품 상세 페이지가 나와야 한다 (로그인 벽 없이).

## 2. 유저 플로우

### 2-1. 구매자 핵심 플로우

```
[진입]
카카오톡 공유 링크 / 인스타 링크 / 직접 접속
    ↓
[상품 상세 페이지] ← 비로그인 상태에서도 볼 수 있어야 함
현재 가격, 참여 인원, 남은 시간, 가격 단계 확인
    ↓
[참여하기 버튼 클릭]
    ↓
[로그인/회원가입] ← 이 시점에서만 요구 (카카오 간편로그인)
    ↓
[옵션 선택] (있는 경우)
수량 선택
    ↓
[결제]
토스페이먼츠 결제창 → 결제 완료
    ↓
[참여 완료 페이지]
"참여 완료! 공유하면 가격이 더 떨어집니다"
카카오톡 공유 버튼 + 링크 복사 버튼 (여기서 공유 전환이 가장 높아야 함)
    ↓
[펀드 진행 중]
가격 변동 시 알림 (카카오 알림톡 — 추후)
    ↓
[펀드 종료]
최종 가격 확정 → 차액 환불 (자동)
    ↓
[배송]
셀러가 직접 배송 → 송장번호 수동 전달 (MVP)
```

**중요한 설계 결정:**

- **비로그인 열람 가능.** 카카오톡에서 링크 눌렀을 때 로그인 창부터 뜨면 80%가 이탈한다. 상품 정보는 누구나 볼 수 있어야 한다.
- **로그인은 결제 직전에만.** "참여하기" 버튼을 눌렀을 때 로그인 안 돼 있으면 그때 카카오 로그인을 띄운다.
- **참여 완료 직후가 공유 골든타임.** 결제 완료 페이지에서 공유 버튼을 가장 눈에 띄게 배치한다. "N명만 더 모이면 가격이 떨어집니다"와 함께.

---

### 2-2. 펀드 상태 흐름

하나의 펀드가 가질 수 있는 상태값이다.

```
DRAFT (초안)
  → 상품/가격 정보 입력 완료, 아직 공개 안 됨
  → DB에 직접 입력하는 단계

OPEN (진행 중)
  → 구매자가 참여(결제) 가능
  → 실시간으로 참여 인원, 현재 가격 단계 변동

CLOSED_SUCCESS (성사)
  → 기간 종료 + 최소 인원 충족
  → 최종 가격 확정 → 차액 환불 처리 → 셀러에게 배송지 전달

CLOSED_FAIL (불발)
  → 기간 종료 + 최소 인원 미달
  → 전액 환불 처리

SHIPPING (배송 중)
  → 셀러가 배송 시작

COMPLETED (완료)
  → 배송 완료 + 정산 완료
```

## 3. 페이지 명세

### 3-1. 메인 페이지 (/)

유저가 처음 들어왔을 때 보는 화면.

**화면 구성:**

- 상단: 로고 + 로그인 버튼 (간결하게)
- 히어로 영역: 현재 가장 핫한 펀드 1개 강조 (이미지 크게 + 현재 가격 + 참여 인원)
- 진행 중인 펀드 목록 (카드 형태, 스크롤)
  - 각 카드에 표시할 것: 상품 이미지, 상품명, 현재 가격, ~~원래 가격~~, 참여 인원, 남은 시간
- 카테고리 필터 탭: 전체 / 닭가슴살 / 프로틴 / 간식 / 음료
- 하단: 간단한 푸터 (서비스 소개, 문의)

**MVP 기준 단순화:**
- 초기에 상품이 3~5개이므로 카테고리 필터는 나중에 추가해도 됨
- 히어로 영역도 첫 상품 1개면 메인 = 상품 상세로 바로 가도 무방
- 검색 기능 불필요 (상품이 적으니까)

---

### 3-2. 상품 상세 페이지 (/fund/[id])

**가장 중요한 페이지. 여기서 "참여"와 "공유"가 발생한다.**

**화면 구성 (위에서 아래 순서):**

**A. 상품 이미지 영역**
- 상품 대표 이미지 (스와이프 가능, 최대 5장)
- 이미지는 1:1 비율, 모바일 화면 가로폭에 맞춤

**B. 가격 + 펀드 현황 영역 (핵심)**
- 상품명
- 현재 가격 (크게, 강조 색상)
- ~~시작가~~ 취소선 표시 (얼마나 떨어졌는지 체감)
- 할인율 배지 (예: "20% 할인 중")

**C. 가격 진행 바 (볼륨 프라이싱 시각화)**
```
시작가 6,500원 ────────●─────── 목표가 4,500원
                    현재 5,800원
                    (47명 참여)
```
- 프로그레스 바 형태
- 각 단계에 마커 표시 (10명, 30명, 50명, 100명)
- 현재 위치 강조
- **"3명만 더 모이면 5,200원!"** ← 다음 단계까지 남은 인원 메시지

**D. 실시간 정보**
- 현재 참여 인원: "47명 참여 중"
- 종료까지 남은 시간: "2일 14시간 32분" (카운트다운)
- 남은 시간이 24시간 이하면 빨간색 강조

**E. 참여하기 버튼 (CTA)**
- 화면 하단 고정 (플로팅)
- "공동구매 참여하기 | 현재 5,800원"
- 누르면 → 로그인 체크 → 옵션/수량 선택 → 결제

**F. 공유 버튼**
- 참여하기 버튼 옆 또는 바로 위
- 카카오톡 공유 / 링크 복사
- "공유하면 가격이 더 떨어집니다"

**G. 상품 상세 정보**
- 상품 설명 (셀러 제공 텍스트/이미지)
- 영양정보 (피트니스 식품이므로 필수)
- 배송 안내
- 공동구매 규칙 안내 (최소 인원, 환불 정책)

**H. 가격 단계 테이블**
| 참여 인원 | 가격 | 할인율 | 상태 |
|----------|------|--------|------|
| 10명 이상 | 6,500원 | - | ✅ 달성 |
| 30명 이상 | 5,800원 | 11% | ✅ 달성 |
| 50명 이상 | 5,200원 | 20% | 🔥 3명 남음 |
| 100명 이상 | 4,500원 | 31% | ⬜ |

### 3-3. 결제 페이지

별도 페이지가 아니라 상품 상세에서 바텀시트(모달) 형태로 처리.

**바텀시트 내용:**
- 상품명 + 현재 가격
- 옵션 선택 (있는 경우 — 예: 맛 선택)
- 수량 선택 (기본 1개, 최대 5개 등 셀러가 설정)
- 총 결제 금액
- "가격이 더 떨어지면 차액을 돌려드립니다" 안내 문구
- 결제하기 버튼 → 토스페이먼츠 결제창 호출

### 3-4. 참여 완료 페이지 (/fund/[id]/complete)

**결제 성공 후 리다이렉트되는 페이지. 공유 전환의 핵심.**

**화면 구성:**
- "참여 완료!" 메시지
- 참여한 상품 요약 (상품명, 결제 금액, 현재 단계)
- **"지금 N명 참여 중 — M명만 더 모이면 가격이 떨어집니다!"**
- **카카오톡 공유 버튼 (가장 크고 눈에 띄게)**
- 링크 복사 버튼
- 인스타 스토리 공유 (가능하면)
- "내 참여 내역 보기" 링크

이 페이지에서 공유가 발생하지 않으면 바이럴 구조가 작동하지 않는다. 공유 버튼이 화면의 중심에 와야 한다.

### 3-6. 로그인/회원가입

별도 페이지가 아니라 모달로 처리.

**MVP 인증 방식: 카카오 로그인만.**

이유:
- 타겟 유저가 카카오톡 공유로 유입됨 → 카카오 계정이 기본
- 네이버, 구글 로그인은 나중에 추가
- 이메일/비밀번호 회원가입은 만들지 않음 (관리 부담)

**최초 로그인 시 추가 수집:**
- 이름 (카카오에서 가져옴)
- 휴대폰 번호 (배송 안내용, 직접 입력)
- 배송지 주소 (도로명주소 검색 API 연동)

### 4-2. 가격 계산 로직

현재 가격을 구하는 방법:

```
1. 해당 펀드의 현재 참여 인원(current_participants)을 가져온다
2. price_tiers에서 min_quantity <= current_participants 인 것 중
   min_quantity가 가장 큰 단계를 찾는다
3. 그 단계의 price가 현재 가격이다
```

예시: 참여 인원 47명, 단계가 10명/6,500원, 30명/5,800원, 50명/5,200원이면
→ 30 <= 47 이면서 가장 큰 것 = 30명 단계 → 현재 가격 5,800원

**다음 단계까지 남은 인원:**
```
다음 단계의 min_quantity - current_participants
→ 50 - 47 = 3명
→ "3명만 더 모이면 5,200원!"
```

## 5. 결제 플로우

### 5-1. 결제 (참여)

```
[프론트] 참여하기 클릭
    ↓
[프론트] 로그인 상태 확인 → 미로그인이면 카카오 로그인
    ↓
[프론트] 옵션/수량 선택 + 배송지 입력(또는 기본 배송지 사용)
    ↓
[백엔드] POST /api/orders/create
    - 현재 가격 조회 (price_tiers 기반)
    - order 레코드 생성 (status: PENDING)
    - 토스페이먼츠 결제 요청 생성
    ↓
[프론트] 토스페이먼츠 결제창 표시
    ↓
[유저] 결제 수단 선택 → 결제 진행
    ↓
[토스페이먼츠] 결제 성공 콜백
    ↓
[백엔드] POST /api/payments/confirm
    - 토스페이먼츠 결제 승인 API 호출
    - order.status → PAID
    - fund.current_participants += order.quantity
    - 현재 단계 재계산 (가격 변동 여부 확인)
    ↓
[프론트] 참여 완료 페이지로 리다이렉트
```

### 5-2. 차액 환불 (펀드 종료 시)

```
[시스템] 펀드 종료 시간 도달 (스케줄러 또는 수동 트리거)
    ↓
[백엔드] 최소 인원 충족 여부 확인
    ├── 미충족 → CLOSED_FAIL → 전체 주문 전액 환불
    └── 충족 → CLOSED_SUCCESS → 아래 진행
    ↓
[백엔드] 최종 가격 확정 (fund.final_price)
    ↓
[백엔드] 모든 주문에 대해:
    - refund_amount = paid_price - final_price (× quantity)
    - refund_amount > 0 이면 토스페이먼츠 부분환불 API 호출
    - order.final_price, order.refund_amount 업데이트
    - order.status → REFUNDED_PARTIAL
    ↓
[백엔드] 배송지 리스트 생성 (구글시트 export)
    → 셀러에게 전달
```

### 5-3. 전액 환불 (펀드 불발)

```
[백엔드] fund.status → CLOSED_FAIL
    ↓
[백엔드] 해당 펀드의 모든 PAID 주문에 대해:
    - 토스페이먼츠 전액 취소 API 호출
    - order.status → REFUNDED_FULL
    ↓
[유저에게 알림] "참여 인원 미달로 펀드가 취소되었습니다. 전액 환불됩니다."
```

### 5-4. 토스페이먼츠 연동 핵심

| 기능 | API |
|------|-----|
| 결제 승인 | POST /v1/payments/confirm |
| 부분 환불 | POST /v1/payments/{paymentKey}/cancel (cancelAmount 지정) |
| 전액 취소 | POST /v1/payments/{paymentKey}/cancel |
| 결제 조회 | GET /v1/payments/{paymentKey} |

**주의사항:**
- 부분환불은 카드 결제만 가능 (계좌이체, 가상계좌 부분환불 불가 — MVP에서는 카드 결제만 허용하는 것이 안전)
- 부분환불 PG 수수료: 환불 시 원래 결제의 PG 수수료는 돌아오지 않음 → 차액이 클수록 PG 수수료 손실 발생

## 6. 카카오톡 공유

### 6-1. 카카오 공유 메시지 구조

카카오톡으로 공유할 때 보여지는 카드 형태의 메시지.

```
┌─────────────────────────────┐
│  [상품 이미지]               │
│                             │
│  닭가슴살 1kg               │
│  지금 5,800원 (11% 할인 중)  │
│  47명 참여 중 | 2일 남음     │
│                             │
│  [공동구매 참여하기]          │
└─────────────────────────────┘
```

**카카오 JavaScript SDK** 사용하여 커스텀 메시지 템플릿 전송.

### 6-2. OG 태그 (링크 미리보기)

카카오톡, 인스타, 문자 등에서 링크를 보낼 때 미리보기에 표시되는 정보.

```html
<meta property="og:title" content="닭가슴살 1kg 공동구매 — 지금 5,800원" />
<meta property="og:description" content="47명 참여 중! 3명만 더 모이면 5,200원" />
<meta property="og:image" content="[상품 대표 이미지 URL]" />
<meta property="og:url" content="https://도메인/fund/[id]" />
```

**OG 태그는 동적으로 생성돼야 한다.** 펀드별로 현재 가격, 참여 인원이 다르므로 서버사이드에서 메타태그를 렌더링해야 한다. Next.js의 generateMetadata 활용.

### 6-3. 공유 추적

모든 공유 버튼 클릭에 UTM 파라미터를 붙인다.

```
https://도메인/fund/[id]?utm_source=kakao&utm_medium=share&utm_campaign=fund_[id]&ref=[user_id]
```

- utm_source: 공유 채널 (kakao, link_copy, instagram)
- ref: 공유한 유저 ID (추후 리퍼럴 보상에 활용 가능)

공유 클릭 시 shares 테이블에 기록.

## 9. 카카오 인앱 브라우저 대응

한국에서 카카오톡 공유 링크를 열면 카카오 인앱 브라우저에서 열린다. 이게 일반 크롬/사파리와 다르게 동작하는 부분이 있다.

**주의할 점:**
- localStorage/sessionStorage 제한이 있을 수 있음 → 인증 토큰은 쿠키 기반으로 처리
- 결제창 리다이렉트 방식이 다를 수 있음 → 토스페이먼츠 연동 시 인앱 브라우저 테스트 필수
- window.open 동작이 다름 → 외부 링크는 target="_blank" 대신 location.href 사용
- 뒤로 가기 동작 확인 → 결제 완료 후 뒤로 가기 시 중복 결제 방지 필요

**테스트 필수 시나리오:**
1. 카카오톡에서 공유 링크 열기 → 상품 상세 보기 → 결제 → 완료
2. 카카오톡에서 공유 링크 열기 → 카카오 로그인 → 결제
3. 결제 완료 후 뒤로 가기 버튼 눌렀을 때 중복 결제 안 되는지

## 11. 추적해야 할 이벤트 (Analytics)

어떤 행동이 발생하는지 측정하지 않으면 개선할 수 없다.

**필수 추적 이벤트:**

| 이벤트 | 설명 | 왜 중요한가 |
|--------|------|------------|
| page_view (fund) | 상품 상세 페이지 조회 | 전체 유입량 |
| click_join | "참여하기" 버튼 클릭 | 구매 의향 |
| login_start | 로그인 모달 표시 | 로그인 벽에서 이탈하는지 |
| login_complete | 로그인 완료 | 로그인 전환율 |
| payment_start | 결제창 진입 | 결제 단계 도달 |
| payment_complete | 결제 완료 | 실제 구매 전환율 |
| share_click | 공유 버튼 클릭 | 바이럴 발생 여부 |
| share_complete | 카카오톡 공유 완료 | 실제 공유 전환율 |
| referer_visit | 공유 링크로 유입 | 바이럴 유입 효과 |

**핵심 퍼널:**
```
페이지 조회 → 참여 클릭 → 로그인 → 결제 시작 → 결제 완료 → 공유
```

이 퍼널의 각 단계 전환율을 매주 확인한다. 가장 이탈이 큰 구간을 먼저 개선한다.

**구현:** Supabase에 events 테이블 만들어서 직접 쌓거나, Google Analytics 4 사용.

## 12. 보안/예외 처리

**결제 관련:**
- 결제 완료 후 뒤로 가기 시 중복 결제 방지 (idempotency key)
- 결제 중 펀드 종료되면: 결제 진행 불가 처리 + 안내 메시지
- 동시에 여러 명이 결제할 때 참여 인원 정합성 (DB 트랜잭션)

**펀드 관련:**
- 최대 인원 초과 결제 방지 (max_participants 체크)
- 펀드 종료 시간 이후 결제 차단
- 한 유저가 같은 펀드에 중복 참여 허용 여부 결정 필요 (허용하되 수량 제한 추천)

**인증 관련:**
- Supabase Auth + 카카오 OAuth
- JWT 토큰 httpOnly 쿠키로 관리 (카카오 인앱 브라우저 대응)
- API 엔드포인트별 인증 체크 미들웨어

## 13. 개발 우선순위

1순위부터 만들어서 배포한다. 1순위 전체가 완성돼야 첫 펀드를 열 수 있다.

**1순위 (필수 — 첫 펀드에 필요)**
- 상품 상세 페이지 (가격 진행 바, 참여 인원, 카운트다운)
- 카카오 로그인
- 결제 (토스페이먼츠 연동)
- 참여 완료 페이지 (공유 버튼 포함)
- 카카오톡 공유 + 링크 복사
- OG 태그 동적 생성
- 마이페이지 (참여 내역)
- 메인 페이지 (펀드 목록)

**2순위 (첫 펀드 직후)**
- 펀드 종료 처리 (차액 환불, 전액 환불)
- 배송지 리스트 엑셀 export
- 이벤트 추적 (analytics)

**3순위 (안정화 이후)**
- 카카오 알림톡 연동
- 배송지 주소 검색 API
- 데스크톱 반응형
